# Roadmap

> **Status: PRODUCT PHASES, NOT RELEASE DATES**

This roadmap separates near-term proof from long-term vision. It does not claim
that a planned capability exists because a design branch or document describes
it.

## 1. Return to owner — active

The immediate threshold is safe daily owner use with known limitations.

Current work focuses on recovery, schema lifecycle, backup/restore, durable
inbound composition and real-process evidence. This threshold is about safety,
not feature completeness.

## 2. DAY-1 Gate — next

DAY-1 requires the full owner-critical inventory to have no unresolved blocker
or unknown status, plus acceptance against the real installation.

The exact inventory remains private and volatile; this public repository does
not duplicate its counts.

## 3. Fourteen days of exclusive dogfood

After DAY-1, the owner attempts to use Muffin as the primary personal agent for
14 consecutive days.

The run is meant to reveal:

- which direct interfaces still cannot be replaced safely;
- what Muffin forgets or misattributes;
- where work disappears, duplicates or resumes badly;
- when proactivity helps and when silence is better;
- which cognitive ideas improve real use and which only sound clever.

Failures become product evidence, not marketing exceptions.

## 4. Trusted alpha

A small external group becomes reasonable only when installation, update,
recovery, security boundaries and support expectations are understandable to
someone who did not build the system.

## 5. Public alpha and open source

Public release requires a source and contributor path that does not rely on
private project knowledge. Documentation, machine-readable descriptions,
security boundaries and current/historical labels must agree.

The current source checkout is not yet that product experience.

## Later directions — PLANNED

- Consumer-grade desktop onboarding and local control plane.
- Portable continuity export/import across versions and machines.
- Remote owner-controlled Nodes and specialised device bodies.
- Capability packages with inspectable authority requests.
- Community discovery and review of optional extensions.
- More surfaces, connectors and importers without expanding the trusted core.

These directions have architecture work behind them, but no public availability
promise or date.
